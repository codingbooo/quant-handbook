Architecture Deepening Review

HNE 核心工程代码架构体检报告

基于 Matt Pocock 《Codebase Design》深模块理论、Deletion Test 与测试缝隙（Seams）分析

108 Tests Passing 17 Python Modules

📐 架构体检总览 (The Depth & Seam Diagnostic)

通过对 /hne/ 下 17 个模块的依赖拓扑、接口宽度及调用位置进行全局审查，我们发现了 3 处显著的“浅模块（Shallow Modules）”与“缝隙泄漏（Seam Leaks）”。当前虽然通过了 108 项测试，但部分业务复杂度（因果级联、持久化协调、双轨存储）泄漏在应用外层控制器（app.py）与多处浅适配层之间。

候选点 1：将双轨状态机合并，打造单一深模块 ChapterLifecycle

Recommendation: Strong (极力推荐)
涉足文件: hne/editor.py, hne/snapshots.py, hne/kanban.py, hne/indexer.py

❌ 当前痛点 (Problem: Shallow & Split State)

目前存在两套并行的章节写入机制：单项目旧版由 Editor + repo.sync_one 管理；多项目沙箱由 TimeMachine.change + Kanban.cascade_invalidate 管理。 每次修改正文，调用方（app.py）需要判断是否有 project 参数来分支调用不同的浅模块。而且快照创建、哈希校验、门禁置 stale、以及因果级联失效（Cascade Invalidation）散落在 3 个文件里。

✨ 深化解法 (Solution: Deep Lifecycle Module)

通过 Deletion Test：删除 Editor 和 TimeMachine，合并成一个纯粹深度的 ChapterLifecycle。对外暴露极小接口（read(), commit(), rollback()），对内自包含原子写入、时光机快照、下游级联冻结、幂等凭证校验。

收益与杠杆 (Leverage & Locality)： 调用方从了解 4 个模块的协同规则简化为调用 1 个方法；后续任何章节正文修改，因果级联保护均 100% 自动闭环触发，绝无漏网之鱼。

候选点 2：统一门禁审查流水线 QualityInspector

Recommendation: Worth exploring (值得推进)
涉足文件: hne/gate.py, hne/quality.py, hne/quality_tiers.py

❌ 当前痛点 (Problem)

gate.py 拥有 366 行精密的正则、密度与大模型红蓝对抗逻辑；而 quality_tiers.py 内部又自己写了一套 evaluate()（硬规则、TTS、悬念分）以及一个独立的大模型调用。 两套门禁的规则逻辑存在重复与割裂，导致维护者修复一个同音词或字数红线时必须在两处同时改动。

✨ 深化解法 (Solution)

将 gate.py 的多级检测能力沉淀为 QualityInspector 的内部适配器（Adapters: L1-Regex, L2-Heuristics, L3-LLM-Clash）。 QualityGateEngine 只作为一个提供极小接口的门面，调用方传入章节文本与世界观，即刻吐出完整的因果与合规报告。

候选点 3：前端大看板 kanban.html 状态与渲染模块化

Recommendation: Speculative (可选演进)
涉足文件: hne/templates/kanban.html (1100+ lines)
当前 kanban.html 集成了 1100 多行内联 JavaScript，集成了作品墙、五阶横向大看板、4个模块化设定独立请求、抽屉编辑器、时光机快照回滚与门禁对抗对比。 虽然单文件非常利于即开即用和静态托管，但状态变更函数散落全局（如 decideCard, saveSetting, openChapterDrawer）。可考虑抽出轻量的 kanban-store.js，让 DOM 渲染与 API 通信解耦。

🏆 首席推荐演进路径 (Top Recommendation)

强烈建议优先执行 【候选点 1：打造单一深模块 ChapterLifecycle】。 通过将旧版单项目兼容逻辑与多项目沙箱快照/级联逻辑收敛至一个深模块中，不仅能一口气删除 2 个浅文件，还能让系统因果断裂级联保护（Cascade Invalidation）成为正文写入时不可绕过的强制契约，使测试覆盖更集中、代码理解更平滑！
