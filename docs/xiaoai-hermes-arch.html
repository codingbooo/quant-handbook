2. 小米云端平台 (Mina / MiIO) 公网云端 / ASR 转写

▼ HTTPS 毫秒级长轮询 (Mina API)
3. 本地桥接网关 (MiGPT / Bridge) 内网服务 / 路由与拦截
以客户端身份常驻内网，毫秒级捕获转写文本。若命中触发词立即给音箱发送打断指令，并将意图派发。
▼ 本地 HTTP / REST (SSE)
4. Hermes 智能中枢 (Agent Runtime) 思考中枢 / 工具 / 记忆
负责深度意图推理、检索本地长期记忆、调度系统工具（查股票、搜网络、控制设备），生成回答回传。
▲ 调用小米 TTS (Text-to-Speech) 指令下发
回传音箱外放 音频流播放
音箱收到文本后，调用小米官方音色库或本地音频流外放，完成交互闭环。

🌐 2. 通信协议与数据流矩阵

链路节点 协议类型 传输内容与机制
音箱 ↔ 小米云端 WSS / TLS 上传原始音频切片（Opus 压缩）；下发原生控制指令与媒体流。
桥接服务 ↔ 小米云端 HTTPS REST 1. 拉取文本: mina.mi.com/remote/ubus 轮询会话记录。
2. 拦截打断: 下发 player_pause 抢断原生回答。
3. 下发播报: 调用 text_to_speech 让指定 DID 音箱发声。
桥接服务 ↔ 音箱 (局域网) MiIO UDP (54321) 可选直连加速方案。利用局域网 Token 下发 TTS 指令，延迟可降至 100ms 级。
桥接服务 ↔ Hermes HTTP / JSON 标准 JSON-RPC 或 REST API，传递问答内容、会话标识及上下文配置。

⚡ 3. 完整交互时序 (唤醒对话全过程)

Step 1: 语音唤醒与拾音
用户说出：“小爱同学，问问 Hermes，今天持仓表现怎么样？” 音箱本地唤醒并推流。
Step 2: 云端转写与事件捕获
小米云转写出文字。本地 Bridge 网关在毫秒级内捕获该转写事件。
Step 3: 命中判定与闪电打断
检测命中触发词 Hermes，Bridge 立即向音箱发出静音/暂停指令，掐断小爱原生的“抱歉我没有听懂”。
Step 4: Hermes 思考与工具调度
Hermes 接收问题，自动调用持仓监控工具拉取最新行情，整理出精炼回答。
Step 5: TTS 下发与语音播报
Bridge 收到答复文本，调用小米 TTS 接口下发到音箱，音箱清晰念出回答。

🛡️ 4. 原生功能互不影响的设计保障

  • 特定前缀过滤：只有包含设定关键词（如“Hermes”、“请教一下”）的语音才会交由智能中枢接管。
