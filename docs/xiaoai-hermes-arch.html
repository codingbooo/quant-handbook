技术边界、风控机制、社区数万活跃用户的实测结论与防御策略
实测结论：极安全 · 零封号案例 · 仅需防范临时限流
🛡️ 权威结论一句话：
不会封小米账号，更不会导致音箱变砖！
xiaogpt / MiGPT 类项目在开源社区已经稳定运行了 3 年以上，GitHub 累积数万 Star、几十万家庭常驻运行。到目前为止，全网没有任何因为个人使用此类开源工具导致小米主账号被封停或硬件被锁的案例。

⚖️ 1. 为什么小米官方不封号？（官方态度与风控机制）

  • 它调用的是合法的官方移动端私有 API：你每次请求都携带了合法的账号 Cookies 和设备身份（模拟手机 App 浏览对话记录），属于正常家庭主人的合法设备控制行为。
  • 不是黑产刷量行为：小米风控系统的雷达主要盯着“黑产短信轰炸、商城抢购脚本、黄牛批量注册”。你一台音箱在家庭内网偶尔说两句话，一天请求量极小，完全不会触发黑产维度的风控。
  • 小米对 Home Assistant / 极客生态向来保持默认包容：整个米家生态之所以繁荣，一大原因就是对开源智能家居社区（如 hass-xiaomi-miot、xiaomi_miot_raw）睁一只眼闭一只眼。小米没有动力因为用户“用自己的音箱听 AI”去封杀自己最核心的高价值极客米粉。

⚠️ 2. 唯一真实存在的“小风险”是什么？

⚠️ 风险 A：云端 API 临时限流 (429 Rate Limit)

现象：如果轮询请求太频繁，可能会暂时返回 429 Too Many Requests，几分钟内无法拉取对话记录。
解法：网关默认都做了指数退避和合理的时间间隔（默认 1 秒左右轮询一次），在正常家庭网络下几乎不会触发。

⚠️ 风险 B：账号登录 Token 30 天自动过期 (401)

现象：连续跑了 1 到 2 个月后，小米云端鉴权 Token 自然过期，音箱突然不再响应 AI。
解法：不是封号，只是 Session 过期。重新跑一下命令更新一下 Cookies 或重启一下容器即可自动刷新。

🛡️ 3. 极客高枕无忧的安全防护建议

  1. 在家庭宽带内网运行（推荐 Mac 本机）：
    直接在你的 Mac mini 或 Mac 本地运行，你的出口 IP 就是你日常手机连 Wi-Fi 的家庭 IP，小米云端判定为“同一个家庭局域网的正常行为”，风控置信度最高。千万不要扔到海外脏 IP 的廉价 VPS 云服务器上跑。
  2. 强迫症双保险：用小米小号（共享音箱）：
    如果你对主账号有洁癖，可以在米家 App 里注册一个专门的小号，在米家中把这台小爱音箱「共享」给这个小号，然后网关只登录小号。这样主账号和任何风险完全物理隔离。
