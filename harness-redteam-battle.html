⚔️ 五轮极限制衡对抗轨迹

Round 1: 基础骨架成型，业务断路致命穿透
REJECTED (5 P0 Flaws)
  • 装配器旁路穿透： assemble_release 仅机械拼装，直接跳过红队模型裁决。
  • 静默吞噬质检异常： 逆向终审 linter 报错被 except 静默吸收，坏包照常发布。
  • 破坏性原地落盘： 直接以 'w' 模式写入正式文件，中途崩溃直接导致文件被腰斩置空。
  • Oracle 上下文暴力截断： 红队审查将正文切片为 [:2500]，大章节后半段违规直接隐形。
🛠️ v2.0 重构响应：
引入强制 .audit.json 凭证门禁，解耦 ChapterValidator 与 ReleaseValidator，引入 tempfile + fsync + os.replace 原生原子写入。
Round 2: 凭证闭环伪造与裂脑发布风险
REJECTED (3 P0 Bypasses)
  • 盲验哈希遗漏裁决断言： 装配器只检查凭证内容哈希是否一致，却漏写了 assert verdict == 'PASS'。
  • 伪造历史基线放行条： force_red_team=False 后门直接为存量章节无成本捏造 PASS 凭证。
  • 双文件非原子切换裂脑： 正文与清单分别执行两次 os.replace，存在跨文件读取严重不一致窗口。
🛠️ v3.0 重构响应：
硬核补充双向 PASS 强断言；引入 HMAC-SHA256 本地密钥加密签名防伪凭证；规划事务发布目录。
Round 3: 内部威胁模型与 OS 级原子事务挑战
REJECTED (2 Deep Architectural Objections)
  • 硬编码 HMAC 密钥穿透： 密钥写死在 Python 脚本内，代码泄露或内部越权将使签名防伪彻底失效。
  • 伪多文件事务原子性： POSIX 规范不存在多文件同时原子重命名的系统调用，跨文件必须上升到目录符号链接层级。
🛠️ v4.0 重构响应：
构建 KeyManager（环境变量 / 0o600 受限密钥文件）；设计 releases/v_xxx/ 版本化目录与 current 单一符号链接原子切换架构。
Round 4: 版本不可变性、异常误杀与并发密钥损坏
REJECTED (4 P0/P1 Blockers)
  • 确定性命名原地覆盖在线版本： 重复构建同版本使用 exist_ok=True 导致已上线文件被 open('w') 实时截断。
  • 提交点未隔离误杀在线版本： except 分支无脑删除整个版本目录，一旦发布生效后日志异常将导致软链接悬挂打崩线上。
  • 虚假历史基线绕过： 仅凭 1 <= ch <= 45 范围签发豁免，黑客修改正文后仍可伪称历史章节绕过审查。
  • strip() 腐蚀密钥字节： 随机 32 字节可能恰好首尾包含 ASCII 空白字符，strip() 裁剪后导致重启后验签全崩。
🛠️ v5.0 重构响应：
构建不可变版本目录（仅允许从 staging 原子提升，目标存在直接抛错阻断）；严格划分 Commit Point 杜绝误杀；建立 1~45 章只读固化的 FROZEN_BASELINE_LEDGER 清单；修复 O_CREAT | O_EXCL 并发密钥初始化；推出 ReaderSnapshot 读者防混版协议。
Round 5: 企业级高可靠收口——由攻击性阻断转入确定性生产收口
CONDITIONAL READY (Enterprise State)
  • 核心主路径全面加固： 破坏性文件截断、在线目录误删、历史基线被篡改等 P0 级严重隐患已 100% 彻底杜绝。
  • 读者快照协议生效： 经实测 ReaderSnapshot 能够瞬时锚定不可变版本物理快照，杜绝高频发布时的正文与清单混版。
  • 存量资产通过只读断言： 1~45 章（86,708 汉字）成功通过 Frozen Baseline 物理验证并顺利完成两阶段事务发布。
  • 待收尾生产级细项： 增加目录级 fsync()、凭证全面 Schema 契约校验（policy_version）、提交后状态查询幂等化。
